# 📝 게시판 프로젝트 #1

---

## 개요
게시판 서비스는 겉보기에는 단순해 보이지만,  
도메인 확장과 요구사항이 추가될수록 얼마든지 복잡해질 수 있는 프로젝트입니다.

본 프로젝트는 **게시판 서비스의 핵심 기능을 직접 설계·구현**하며,  
데이터베이스 설계, 인증/인가, 테스트, 코드 구조에 대한 이해를 목표로 합니다.

---

## 1주차 목표
**게시판 서비스 #1 – Database 설계 및 Spring Boot 웹 애플리케이션 서버 개발**

---

## 요구사항

### 1️⃣ 데이터베이스 설계 (ERD)

AI 도구를 활용하여  
[DBDiagram](https://dbdiagram.io/d) 에서  
[DBML](https://dbml.dbdiagram.io/docs/) 언어로 ERD를 설계합니다.

#### 데이터베이스 ERD 설계 요구사항

- **글과 댓글**
    - 게시글에 댓글을 달 수 있어야 합니다
    - 댓글에는 대댓글을 달 수 있어야 합니다 (계층 구조)

- **북마크**
    - 사용자는 좋아하는 게시글을 북마크할 수 있어야 합니다
    - 북마크한 게시글을 나중에 모아서 조회할 수 있어야 합니다

- **카테고리**
    - 게시글은 여러 카테고리에 속할 수 있어야 합니다
    - 사용자는 새로운 카테고리를 자유롭게 추가할 수 있어야 합니다

> ERD 설계 시, 각 테이블 간의 **연관관계와 책임 분리**를 명확히 표현해야 합니다.

---

### 2️⃣ Spring Boot API 개발

AI 도구를 사용하지 않고,  
**본인이 직접 Spring Boot를 통해 API를 개발**합니다.

#### 로그인 및 보안 요구사항

- 로그인은 **세션(Session) 기반**으로 유지합니다
- 로그인한 사용자는
    - **자신이 작성한 글만 수정/삭제 가능**
    - **자신이 작성한 댓글만 수정/삭제 가능**
- 권한은 아래 두 가지로 구분합니다
    - `USER`
    - `ADMIN`
- **ADMIN 권한을 가진 사용자만 Swagger 페이지에 접근 가능**해야 합니다

---

### 3️⃣ 테스트 코드 작성

AI 도구를 활용하여  
**Spock 또는 JUnit 중 하나를 선택**하여 테스트 코드를 작성합니다.

#### 테스트 요구사항

- **BDD (Behavior-Driven Development)** 스타일을 따릅니다
    - Narrative
    - Given – When – Then 구조
- 유닛 테스트 코드를 실제로 실행하여 통과해야 합니다

---

### 4️⃣ 코드 리뷰 (디자인 패턴 / 아키텍처)

AI 도구를 활용하여  
**본인이 직접 작성한 코드에 대해 코드 리뷰를 수행**합니다.

#### 리뷰 대상

- Controller
- Service
- Repository
- 그 외 본인이 작성한 모든 코드

#### 리뷰 관점

- 디자인 패턴 관점에서의 개선점
- 아키텍처 및 책임 분리 관점에서의 개선점
- 코드 가독성 및 유지보수성

---

## 원칙

- 프로젝트는 **정상적으로 빌드되고 실행되어야 합니다**
- Controller / Service / Repository 간의 책임을 명확히 분리해야 합니다
- 도메인 모델 중심으로 설계하며, 비즈니스 로직이 Controller에 포함되지 않도록 합니다
- 요구사항에 명시되지 않은 사항은
    - **개발자가 자유롭게 가정하고**
    - **자의적으로 해석하여 구현**합니다

## 협업 및 형상 관리

- 변경 사항은 **의미 있는 branch 단위**로 나누어 관리합니다

- PR 작성 시 아래 내용을 포함해야 합니다
    - 변경 사항에 대한 설명

- PR 발행 후 즉시 병합해도 무방합니다
